# Caelush 官网下载首页设计说明

## 项目名称

- 文件夹名：Caelush-Website
- 页面域名：caelush.com.cn
- 首发版本：1.0.0
- 首发平台：Windows 64 位

## 目的

为 Caelush 做一个简洁的中文宣传与下载首页，让第一次访问的个人开发者快速知道 Caelush 能做什么，并直接下载 Windows 安装包。

首页首要目标是促成下载。页面介绍围绕一条清楚的工作流程展开：理解项目、修改代码、运行命令、验证结果。

## 已确认的设计选择

- 白色背景，借鉴 DeepSeek Harness 的居中首屏和突出下载入口，使用 Caelush 自己的 Logo 和文案。
- 首版简体中文。
- 首屏不放产品截图或产品大图；后续可由产品方补充视觉设计。
- 首页采用方案 A：居中标题和简短说明，首屏中央放显眼的 Windows 下载按钮。
- 点击按钮后直接下载安装包，按钮附近显示版本 1.0.0 和 Windows 64 位信息。
- 页面向下继续介绍编程工作流、三项核心能力、系统要求和常见问题。
- 三项能力：项目级代码操作、可控执行、任务可恢复。
- 网站先作为静态页面部署；官网本身不另建后端。

## 页面内容草案

### 1. 顶部导航

- Caelush Logo
- 产品能力
- 下载
- 常见问题

导航项锚点滚动到首页对应区块。手机屏幕上可缩成 Logo 和下载按钮。

### 2. 首屏

文案暂定：

> 让 AI 走完整个开发流程

说明暂定：

> 从理解项目、修改代码，到运行命令并验证结果。

主按钮：

> 下载 Windows 64 位版

按钮周围标记：

- 正式版 1.0.0
- Windows 64 位
- 最低 Windows 版本须从最终打包配置确认后再写，不能猜测

### 3. 工作流程

用一行简洁步骤表达：

> 理解项目 → 修改代码 → 运行命令 → 验证结果

### 4. 三项核心能力

- **项目级代码操作**：阅读、搜索和修改现有项目代码。
- **可控执行**：在权限边界内执行开发操作，需要时请求用户确认。
- **任务可恢复**：保留任务进度，之后可以继续处理。

正式发布前需核对这些描述与 1.0.0 的实际功能一致。

### 5. 系统要求与常见问题

只列出已经核实的信息。首发至少确认 Windows 版本要求、安装包大小以及安装后是否需要单独配置模型服务。

### 6. 页脚

保留 Caelush 品牌信息，以及版本说明、帮助等链接。没有对应页面时不展示失效链接。

## 前端与部署方案

- 技术栈：Nuxt（Vue 3）+ TypeScript + Tailwind CSS；Nuxt UI 只用于需要的通用组件，首屏主体按 Caelush 品牌自定义。
- 使用 Nuxt 静态生成，构建产物由 Nginx 作为静态文件提供。
- 首页下载按钮使用安装包 HTTPS 地址，不通过网页后端中转，也不调用 Cloud API。
- 网站内容先固定显示 1.0.0；后续发布新版本时再更新下载地址与版本文字。
- Caelush-Cloud 继续承担桌面客户端的账号与更新检查职责，不作为官网内容管理服务。

## 安装包下载路径

规划使用版本固定的地址：

https://releases.caelush.com.cn/1.0.0/Caelush-Setup.exe

安装包准备好后，服务器需在该地址提供真实文件，并以下载响应方式返回。正式启用按钮前，需通过 HTTPS 实际下载验证文件存在且内容正确。

DNS 已有 @、www 和 releases 记录指向现有服务器。服务器当前 Nginx HTTPS 配置已知只覆盖 api.caelush.com.cn；网站和安装包域名还需补齐各自的 Nginx 站点配置与证书。变更时保留现有 API 配置。

## 备选方案

- **方案 A（已选）**：居中介绍，下载按钮放在首屏中央，工作流和能力介绍放在下面。优势是访客一打开页面就能看到下载入口。
- **方案 B**：把版本和平台集中放进下载卡片。优势是版本信息更醒目，首屏下载入口占用空间也更多；本次未选。

## 本次范围

包含中文首页结构、首发下载按钮与版本信息、静态站点构建方式、安装包直链规划。

暂不包含产品大图、英文版本、账号注册流程、动态版本后台、应用内更新发布、安装包构建和正式生产部署。安装包尚未打包，真实下载按钮需等安装包上传及 HTTPS 验证完成后启用。

## 验收标准

- 首页以白色背景和 Caelush 品牌展示。
- 首屏清楚介绍产品价值，并突出 Windows 64 位下载入口。
- 页面显示正确版本 1.0.0，不把开发版 0.1.0 当成公开版本。
- 下载按钮只指向经过验证的正式安装包；文件未准备好时不展示可用的坏链接。
- 手机与桌面浏览器中内容都能正常阅读和操作。
- 页面可静态构建并由现有 Nginx 提供服务。

## 实施时锁定的具体细节

- 下载配置集中在网站源码的一处，包含版本 1.0.0、Windows 64 位、安装包 HTTPS 地址和下载启用状态。
- 初始下载启用状态为 false。页面此时显示安装包准备中，不能渲染可点击的下载链接。
- 仅在安装包已上传到目标地址、HTTPS 正常且文件确认正确后，由产品方把启用状态改为 true。
- 公开版本文字、平台文字和下载地址不能各自散落在多个组件内。
- 系统最低版本、安装包大小和模型服务配置均待实际产品核实，不得自行补写猜测值。
- 官网只生成静态文件；官网访问和下载均不依赖新增的 Nuxt 服务端 API。
- 本次实施只修改网站目录。服务器、DNS、Nginx、安装包发布与生产上线留待后续人工部署任务。
